# 0002 · 前端外壳与状态架构（四区布局 + 单一 store + 注册表）

- 状态：已采纳
- 日期：2026-10-28
- 相关：`docs/refactor/frontend-redesign.md`、决策 0032

## 背景

重构前的前端是一个 `main.ts`（约 2150 行）加若干模块：所有界面都挂在一条可滚动的
内容区里，任何数据变更都调用一次 `render()` 做整页 `replaceChildren` 重建。带来三类
结构性问题：

1. **交互被打断**：拖动对比分割线、在输入框里输入、调整拉杆时，只要后台回了进度或
   状态栏更新，整块 DOM 就被替换，焦点、拖拽会话、查看器视口全部丢失。
2. **信息组织失控**：选图、跑分参数、编码阶梯、结果表、视频区块自上而下堆叠，窗口
   高度有限，用户要在长页面里来回滚动；结果表与查看器不可能同时看全。
3. **扩展成本**：新增一个功能域（结果表、视频）必须改 `main.ts` 的渲染分支，模块之
   间靠共享模块级变量通信，测试只能对着源码字符串切片做守卫。

## 决策

1. **四区布局**：顶栏（品牌 / 当前组与轮 / 状态）、左栏（跑分组）、中部工作区（工作栏
   → 舞台 → 结果坞）、右栏检视器（来源 / 跑分 / 编码阶梯 / 高级）。舞台常驻并可沉浸，
   结果坞可折叠、高度可拖拽，检视器与结果坞各自独立滚动。
2. **单一状态源 + 分区渲染**：`src/core/store.ts` 持有工作区、设置、FFmpeg 状态、长任务
   忙状态与状态栏；所有 IPC 变更都用返回的整份工作区替换状态并通知订阅者。外壳把
   界面拆成舞台 / 检视器 / 结果坞 / 三个框，各自 `mount` 一次、状态变化只调 `update()`，
   禁止整页重建。
3. **注册表解耦**：功能域通过 `registerStageView` / `registerPanelSection` / `registerDockTab`
   / `registerCommand` / `registerKeyBinding` 接入外壳，外壳不认识具体功能；命令 id 与
   分区 order 成为跨域契约。
4. **设计令牌**：`src/styles/tokens.css` 是颜色、字号（三档）、圆角、间距、动效的唯一
   真源；功能域只写自己的样式文件，用令牌不写字面值；`design-guards.test.ts` 用纯文本
   扫描守住中点分隔符、粗边框、字号失控、`innerHTML`、字面色值与裸 `invoke`。
5. **纯逻辑可测**：DOM 层不写单元测试（仓库没有 jsdom），把可测的规则（视口数学、
   排序、格式化、脏标记、编码阶梯）留成无 DOM 依赖的纯函数并保留测试；界面用真实桌面
   窗口截图验收。

## 放弃的选项

- **迁移到 React/Vue**：会引入整条构建链与新依赖，收益主要是开发效率；当前界面规模
  与团队（单人 + AI）下，原生 DOM 加明确的原语层足够，且能保持零运行时依赖与现有
  IPC 契约不变。
- **每个分区自己调 IPC 并局部刷新**：会产生多份状态与竞态；后端已按「整份工作区」返回，
  统一替换再分发更简单可靠。
- **虚拟滚动 / 表格组件库**：结果表常态十几行、上限几十行，原生表格足够；虚拟化会带
  来测量与焦点复杂度。
- **继续沿用 `main.ts` 单文件**：无法解决交互打断与模块边界问题，注册表方案让增量重构
  可以按域并行落地。

## 影响

- 新增文件都落在 `src/core`、`src/ui`、`src/shell`、`src/features/*`、`src/styles/*`；
  旧的 `src/main.ts`、`src/style.css` 与一批模块被删除（见提交记录）。
- 新增界面偏好（栏折叠、结果坞高度、列显隐、查看器模式）只写 `localStorage`，键前缀
  `pixel-arena.ui.`，并受「记住上次状态」开关门控；工作区数据格式不变。
- 动效策略：功能反馈始终保留，只有装饰性循环动效尊重系统「减少动态效果」——两个 skill
  口径冲突时取交集，详见决策 0032。
