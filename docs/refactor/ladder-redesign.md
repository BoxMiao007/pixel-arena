# 编码阶梯重构方案：单点 / 阶梯 / 目标大小

> 本文记录 2026-11-03 编码阶梯重构的**设计方案**（即方案评审时发给维护者的那一版）。
> 设计与落地结果的对应关系见决策 0042；本文末尾「验收结果」是重构完成后的实测结论。
>
> 日期：2026-11-03　落地提交：`28f8add refactor(encoding)!: 编码阶梯改为单点/阶梯/目标大小三方式`

---

## 一句话

把现在「两种模式 + 单点开关 + 格式胶囊 + 逐点取消」四层控制，收成**三种互斥方式 + 一张可勾选的阶梯矩阵 + 一个主按钮**：预览就是要生成的清单，大小优先先探测再生成，生成后只跑新产物。

---

## 一、当时为什么乱（有据可查）

1. **模式和单点开关交叉**：`sections/ladder.ts` 里单点开启后模式按钮仍可点但直接 `return`，滑杆被整块替换成文字；想换基准质量必须先关开关。这正是 #67 指出的「两套表达」。
2. **两套勾选作用于同一批点**：格式胶囊改 `selection`，预览里的逐点 chip 改 `excluded`；取消一个格式后整行消失，排除点还会在参数变化时静默清空。
3. **预览 ≠ 将生成**：大小优先的预览只含有损格式，生成清单却含无损；预览只显示 `q75`，不显示实测字节，用户看不到「命中」。
4. **探测是隐式的**：未探测时生成按钮仍可点，内部偷跑搜索；按钮文案写「生成 3 份」，实际会生成 12 份。
5. **失效不完整**：换原图不清 `sizeOutcomes`，旧图实测字节会复用到新原图；`encoderIssue` 修好后不消失；忙时参数仍可改。
6. **生成后整轮重算**：生成一次等于把整轮跑分图全部重算，慢且不可预期。
7. **历史原因**：#67/#72 已在 0.2.1 分支做过三选一与「同一根滑杆换义」，但该分支未合入本树；当前代码仍是 0.1.5 口径。本次是在新前端里重新落地并进一步收口。

## 二、目标设计

**方式**：`[单点] [阶梯] [目标大小]`，默认「单点」；「单点模式」开关彻底消失。

**主参数**（同一位置随方式换义）：

- 单点 / 阶梯：基准质量滑杆（0–100，默认 75），行内注明「各格式按自身范围映射（JXL 上限 95）」。
- 目标大小：目标大小滑杆（1 KB–20 MB 对数刻度，1000 步）+ 精确输入框 + KB/MB；滑杆只做粗调，输入框可超出 20 MB。

**一张矩阵**（4 个有损 + 3 个无损，共 7 行）：

- 行首格式胶囊是**唯一**勾选控件；格子只读，不能再逐点取消。
- 单点：`[JPEG ✓] q75`、`[JXL ✓] q95`。
- 阶梯：`[JPEG ✓] q60 q75 q90`。
- 目标大小：探测前显示「待探测」；探测后每格显示 `q72（198 KB）`，命中格高亮，不可达在行尾给一句中文标注。
- 无损行默认不勾，格子写「无损」；行组上方一行小标题「无损对照（默认不选）」。

**主按钮**：

- 单点 / 阶梯：「生成并跑分」。
- 目标大小：未探测时「探测目标大小」，探测完成后「生成并跑分」；有失败格式时给「重试探测」/「重新探测」。
- 按钮上方只写事实：「将生成 4 项」/「先探测 4 个格式」/「2 个格式探测失败，可重试或取消勾选」。

**进度与失败**：生成 `N/M`、跑分 `N/M` 同一条进度条；失败项就地展开；进行中写明「完成前无法中止」，不放假取消按钮。

**默认值**：单点、基准 75、有损全选、无损不选 → **4 项**；切到阶梯全选 → 12 项。

## 三、实现改动（按子系统）

### 1. 状态与纯逻辑

- `mode: 'single' | 'ladder' | 'size'`；删除 `singlePoint`、`excluded`。
- `defaultSelection()` 改为「有损全选、无损空」。
- **两个独立缓存**，互不误伤：
  - 质量轴 `ladder + ladderKey`：只在方式或基准变化时清空；
  - 大小轴 `sizeOutcomes + sizeErrors + sizeKey`：只在目标或原图变化时清空；
  - 切方式不再清另一轴，避免来回切重复探测。
- `referenceKey = path + size`；变化时清大小缓存、`failures`、`encoderIssue`。
- 纯函数 `buildLadderPreview(state)` 作为**唯一数据源**，返回 `rows / plan / count / pendingFormats / failedFormats / notes / existing`；界面渲染和生成入参都用它，保证「所见即所跑」。
- 纯函数 `bytesFromSlider / sliderFromBytes`（1 KB–20 MB、单调、往返误差 <2%、越界夹住）。
- 保留 `runLadder` 编排、`toggleFormat`、`sizeOutcomeLadder`、`losslessLadder`。

### 2. 动作层

- `loadLadder`：单点走 `onestop_single_point_ladder`，阶梯走 `onestop_quality_ladder`；失败给「重试取点」。
- `probeSize`：逐格式探测；单格式失败记 `sizeErrors` 并继续其余；「重新探测」先清再跑；探测前也做编码器预检。
- `generateLadder`：有 `pendingFormats`/`failedFormats` 时拒绝生成，**不再隐式探测**；按 `preview.plan` 生成；一次性入轮；随后**只对本次新产物**调 `round_score_candidates({ paths })`。
- 参数、格式、原图变化时清 `encoderIssue`；问题卡加「重新检测」。
- 单失败不回滚；冲突沿用「覆盖/跳过/全部」。

### 3. 分区 UI 与样式

- 重写 `render`：方式 segmented、主参数、矩阵、动作、进度、失败。
- 矩阵行首用 `chip` 做格式开关（`aria-pressed`），格子用只读文本/`badge`；无损行只加分隔标题，不加第二组控件。
- 忙时用 `<fieldset disabled>` 包住参数与矩阵，动作按钮单独 `disabled`。
- 滑杆拖动只更新读数，松手（`change`）才取点/清缓存重画，避免拖到一半控件被重建。
- 目标大小非法用 `field({ error })` 就地报错，不再只写状态栏。
- 目录加载失败、取点失败、探测失败都在分区内给重试。

### 4. 文档

- `docs/decisions.md` 新增 **0042**。
- `README.md` 两处一站式段落、`GLOSSARY.md` 相关词条同步；删除旧口径。
- `docs/refactor/encoding-spec.md` 加「由决策 0042 取代」说明；`frontend-redesign.md` §3.3 同步。
- CLI 行为不变；只把帮助文案从「质量优先模式」改为「质量阶梯方式」。

### 5. 明确不做

- 不改工作区数据模型，不改 IPC 命令，不改核心库取点算法。
- 不做重复生成去重：仍按冲突策略追加 `_1`；但预览会把「本轮已有相同档位」标出来。
- 不恢复 0.2.1 的 #70（AVIF/JXL 代片改造）与 #73（原生目标大小参数），单独排期。
- 不动参数变体编码卡（另一条交互线）。

## 四、边界与失败模式

| 情况 | 行为 |
| --- | --- |
| 无原图 / 无格式 / 0 项 | 主按钮禁用，正文写下一步 |
| 目标大小非法（≤0、非数字） | 输入框下就地报错，不落状态 |
| 目标大小改了 / 换了原图 | 清探测结果，回到「待探测」；旧图字节不会复用 |
| 单个格式探测失败 | 该行标「探测失败 + 原因」，其余保留；可重试或取消勾选 |
| 编码器缺失 | 探测/生成前预检拦截，问题卡给「打开设置 / 复制发布页 / 重新检测」 |
| 生成冲突 | 沿用覆盖/跳过/全部；跳过记一条失败，不回滚已成功项 |
| 部分生成失败 | 成功项照常入轮并跑分；失败项就地列出 |
| 忙 | 参数与矩阵禁用，禁止重复触发；如实显示「完成前无法中止」 |
| 取点 / 目录加载失败 | 分区内显示原因 + 重试按钮 |
| 同一档位重复生成 | 预览标「本轮已有」；生成仍新增一份（本轮不做去重） |

## 五、测试与验收

**前端单测**

- 三种方式的 `plan/rows/count`；JXL 上限 95；无损默认不选。
- `buildLadderPreview`：预览 `plan` 与生成入参完全一致；探测前不出可生成清单。
- 缓存失效：改基准只清质量轴；改目标/原图只清大小轴；切方式不清另一轴。
- 滑杆映射：两端、单调、往返误差、越界夹住。
- `probeSize`：单格式失败继续其余；重试只补缺失/失败。
- `generateLadder`：有 pending/failed 时零调用。

**四门**：`cargo test --workspace` → `npm run typecheck` → `npm test` → `cargo run -p pixel-arena-cli -- --version`。

**手工验收（附桌面截图）**

1. 默认展开：单点、q75、4 项、无损三行未勾。
2. 切阶梯：q60/q75/q90，12 项；勾 PNG 变 13 项。
3. 目标大小：探测前「待探测」；探测后显示实测字节、命中高亮、不可达标注；改目标立即清空。
4. 换原图：探测结果清空，不沿用旧图字节。
5. 单点生成：结果表只新增新行，原有行的指标不变。
6. 忙时：参数、矩阵、按钮都禁用，进度真实。
7. 全界面不再出现「单点模式」四个字；预览项数 = 实际生成项数。

## 六、取舍与风险

- **默认改单点 / 无损不选**会推翻 0003 的默认，但这是 #67 的明确诉求。CLI 默认保持 3 点阶梯，文档写明差异。
- **移除逐点取消**：想要自定义档位目前只能选单点或阶梯；未来可加「自定义质量点」方式。
- **大小优先多一步探测**：换掉「偷偷探测 + 数字对不上」的不可预期。
- **标签改名**：推荐「单点 / 阶梯 / 目标大小」，因为旧名两个都以「质量」开头，并列时无法一眼区分。
- **重复生成仍会产生新行**：本轮不解决，记为后续。
- **无取消**：后端没有取消通道，界面不假装能中止。
