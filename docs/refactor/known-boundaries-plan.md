### P1 · 生成去重（同档位不重复新增）

**要解决的问题**

同一轮重复点「生成并跑分」会按冲突策略自动追加 `_1/_2`，结果表堆出同格式同质量的多行；用户无法判断哪行是新的、哪些是旧的。现有去重只按路径（`workspace.rs` 的 `add_round_candidates_with_params`），自动改名后路径不同，等于没去重。

**推荐做法（A1，前端标签匹配，不改数据模型）**

- 身份口径：`LadderItem.label`（如 `JPEG q75`、`WebP 目标 20000 字节`）与后端 `encoding_params_text` 同源；用它和本轮已有 `candidate.encodingParams` 比对。
- 预览：
  - 已有且**已跑分**（`metrics !== null` 且 `error === null`）的项：标「本轮已有，将跳过」。
  - 已有但**未跑分 / 跑分失败**（产物已在轮里）的项：标「本轮已有，将补跑分」——不重新生成文件，只把它加入本次跑分集合。
  - 没有对应候选行的项（生成阶段就失败）：正常重试生成。
- 生成：
  - 跳过「已有且已跑分」的项；不生成新文件。
  - 本次跑分集合 = 新产物路径 + 被跳过但缺指标的旧产物路径。
  - 加一个「重新生成已存在的档位」复选框（默认关）；勾上时全部按新产物生成，走原冲突策略。
- 边界：
  - 换了编码器设置（同一参数文本、不同实际参数）时，标签匹配会误判「已有」；「重新生成」复选框是显式逃生口，文档写明。
  - 换原图后旧行指标会被后端清空，匹配项自动落入「将补跑分」分支，不会留下未跑分的行。
  - 外部导入的图 `encodingParams` 为 null，不会被误匹配。

**备选（A2，结构化档位身份）**

给候选行加结构化字段后按 `format + quality/targetBytes + source + 原图标识` 匹配，语义更稳；但需要 P4 的数据模型改动。建议 A1 先落地，P4 完成后再把匹配升级为结构化（或直接由 P4 取代 A1 的字符串匹配）。

**验收**

- 同一份清单连续生成两次：第二次新增 0 行，状态栏说明「N 项已存在，跳过」。
- 旧行有缺指标/失败时，第二次只补跑分，不新增文件。
- 勾「重新生成已存在的档位」后仍按原冲突策略生成新行。
- 单测：预览跳过/补跑分分类、生成入参、跑分集合；手工实测一次。

**写作用域**：`src/features/encoding/logic/ladder.ts`、`session.ts`、`actions.ts`、`sections/ladder.ts`、对应测试；不改 Rust。

### P2 · 长任务取消

**要解决的问题**

编码、跑分、目标大小探测都是长任务；目前全仓没有取消通道，用户只能等。后端命令在 `spawn_blocking` 里持工作区锁，整批跑完才返回；前端只能禁用重复触发。

**推荐做法（B1，分阶段）**

1. **前端生成循环取消**（先做，收益最大、风险最低）：
   - `runLadder` 接受 `isCancelled()`；每项开始前检查，取消后不再生成后续项；已生成产物照常入轮。
   - 取消按钮出现在生成进度条旁；状态栏「已取消，已生成 N 项」；已生成项是否继续跑分由实现定：推荐**取消后不再自动跑分**，让用户决定是否点「开始跑分」。
2. **后端评分取消**：
   - `AppState` 增加 `cancels: Mutex<HashMap<String, Arc<AtomicBool>>>`；新 IPC `cancel_task(task_id)`。
   - `round_score_candidates` 接受 `taskId`，注册 token；核心评分循环在每张图开始前检查 token，取消后停止派发、保留已完成行的指标、写盘并返回部分结果。
   - 前端在跑分进度旁给「取消」，调用 `cancel_task`；命令返回后 `endBusy`，状态「已取消，已完成 N/M」。
3. **探测取消**：
   - 前端 `probeSize` 的逐格式循环检查 token；当前格式内部的 2–8 次探测允许跑完（粒度可接受）。
4. **子进程强杀（暂不做）**：
   - 单个编码项（`onestop_encode`）内部是编码器子进程；要「立刻中止」需要持有子进程句柄并跨平台 kill。先不做，界面如实说明「当前项完成后停止」。

**语义**

- 不rollback：已写出的产物、已更新的指标保留；取消只停止后续项。
- 进度不伪造：取消中显示「正在取消，等待当前项完成」，不显示假的百分比。
- 忙标志一定 `endBusy`（`try/finally`），否则界面会永久灰死。

**验收**

- 12 项阶梯生成中点取消：最多再完成当前 1 项，之后不再生成；已生成项在结果表/分区可见；状态栏说明取消。
- 跑分批中点取消：已完成行有指标，后续行保持待跑分；不再继续调用后端。
- 探测中点取消：已探测格式保留，未探测格式回到「待探测」。
- 单测：token/循环停止/部分结果；手工实测一次。

**写作用域**：`src-tauri/src/lib.rs`、`crates/pixel-arena-core` 的评分/探测循环、`src/core/store.ts`（如需取消按钮状态）、`features/encoding/{logic/ladder.ts,actions.ts,sections/*}`、`features/results` 的跑分进度入口、测试。

### P3 · #70 AVIF/JXL 按需解码，停写 `.png` 代片

**要解决的问题**

当前编码 AVIF/JXL 会在产物旁写 `<产物>.png` 代片（`encode.rs:write_view_proxy`）；查看器一律把 `.avif/.jxl` 映射到 `.png`（`model.ts:proxyPathFor`、`viewer/stage.ts`）。后果：
- 产物目录混入代片，分享/归档要手动挑；
- 人工导入的 AVIF/JXL、以及作为原图的 AVIF/JXL 没有代片，查看器必然破图；
- 代片只覆盖产物，不覆盖外部来源。

**做法（按 #70 的规格，适配本树）**

1. **核心库**：
   - `encode_onestop` 里把「自检解码 + 写代片」改成「只解码自检（内存）」，解不开仍判该档失败并删产物；删除/停用 `write_view_proxy` 的产物调用。
   - 旧 `.png` 不删除、不改动。
2. **Tauri 新 IPC `image_view_path(path)`**：
   - 非 AVIF/JXL 直接返回原路径。
   - AVIF/JXL 用现有 `decode_srgb`（avifdec / jxl-oxide）解码，写无损 PNG 到系统临时目录 `pixel-arena-view/`，按「路径 + 大小 + 修改时间」缓存复用；返回临时 PNG 路径。
   - 解码失败返回中文原因；临时目录有容量/数量上限，启动时清理过期文件。
3. **前端查看器**：
   - 新增 `resolveViewPath(path)`（异步、带缓存）；`ui/canvas.ts` 的 `loadImage` 前先解析；解析中显示 spinner，失败走现有「无法显示」空态并给原因与重试。
   - `core/model.ts` 的 `isProxyFormat`/`proxyPathFor` 下线或改为「需要按需解码」判定；`viewer/stage.ts` 所有 `${path}.png` 映射删除。
   - 右键菜单/另存/打开位置仍用真实路径，不受影响。
4. **兼容**：
   - 磁盘上旧 `.png` 代片保留但不再被读取；新逻辑不依赖它。
   - asset protocol 的 scope 已是 `**`（`tauri.conf.json`），临时目录路径可直接被 `convertFileSrc` 加载。

**验收**

- 生成 AVIF/JXL 后产物目录只有真产物，没有新 `.png`；查看器仍能显示。
- 外部导入的 AVIF/JXL、以及 AVIF/JXL 原图都能在查看器显示。
- 解码失败给中文原因与重试；不崩、不空白。
- 旧 `.png` 不被删除、不被改动；删除真产物后临时缓存能被识别/清理。
- 单测：核心自检失败、临时路径缓存、查看器解析；手工三种来源截图。

**风险**

- 查看器所有模式的加载入口都走 `loadImage`，异步解析要覆盖分屏、多视图、滑动、叠加、差异、闪烁（视频无关）；漏一个入口就会出现「有的模式能看、有的不能」。
- 首次打开 AVIF/JXL 会有一次解码等待；要显示 loading，不能假装秒开。
- 临时目录清理策略要防「文件被查看器占用删不掉」，失败静默跳过即可。

**写作用域**：`crates/pixel-arena-core/src/{encode.rs,decode.rs}`、`src-tauri/src/lib.rs`、`src/core/{model.ts,ipc.ts}`、`src/ui/canvas.ts`、`src/features/viewer/**`、测试。

### P4 · 结构化档位持久化 + 结果表格式列

**要解决的问题**

候选行只存 `encoding_params` 文本；结果表的「格式」列靠扩展名推（有损 WebP 与无损 WebP 都显示 WebP），质量档没有结构；后续「格式对比」表、原生目标大小、导出都只能解析文本或靠启发式。

**做法**

1. **数据模型**（`workspace.rs` + `core/model.ts`）：
   - `CandidateImage` 增加可选字段（旧文件缺失为 `None`）：
     - `format: Option<String>`（jpeg/webp/avif/jxl/png/webp-lossless/jxl-lossless）
     - `lossless: Option<bool>`
     - `quality: Option<u8>`
     - `target_bytes: Option<u64>`
     - `native_target: Option<bool>`
     - `source: Option<String>`（ladder / variant；外部导入为 None）
     - 可选 `ladder_mode: Option<String>`（single/ladder/size）
   - `FORMAT_VERSION` 升到 2；加载器接受 1/2，v1 迁移为字段全 `None`；新写一律 v2。旧应用读 v2 会拒绝（安全，不静默丢字段）。
2. **写入链路**：
   - `onestop_encode` / `advanced_encode` 的产物回包带结构化 meta；`round_add_candidates` 扩展参数（或新增 `round_add_candidates_meta`），一次性写入路径 + 参数文本 + meta。
   - 外部导入的 `round_add_candidates` 保持 meta 全 None。
3. **结果表**：
   - 「格式」列改为「结构化 format 优先，缺失时回落扩展名」；无损 WebP 与有损 WebP 可分。
   - 编码参数列仍显示 `encoding_params`（兼容旧数据）。
   - 原生目标大小（P5）显示「目标大小（无质量）」；质量档显示 qN。
4. **导出/CLI**：
   - 既有 CSV 列序不变（兼容）；是否追加 `format/quality` 列单独拍板（建议先只在 HTML/JSON 加，CSV 保持）。
   - CLI 不写工作区，但 P5 的 CSV/JSON 质量列需要同步。

**验收**

- 旧 v1 工作区能加载、保存后变 v2、旧行 meta 为 None；新行有完整 meta。
- 结果表「格式」列能区分有损/无损 WebP；质量/目标大小显示正确。
- 旧应用打开 v2 工作区给明确错误（不静默改坏）。
- 单测：serde 往返、v1→v2 迁移、v2 拒绝旧版、结果表 format 回落。

**风险**

- 工作区格式是用户数据，迁移必须只加字段、不改既有语义；提交前用真实旧工作区副本跑一次加载/保存。
- `encoding_params` 仍是界面主显示，结构化字段只做「更准的派生」，不要两套文案打架。

**写作用域**：`crates/pixel-arena-core/src/workspace.rs`、`src-tauri/src/lib.rs`、`src/core/model.ts`、`src/features/encoding/{ipc.ts,actions.ts,logic/ladder.ts}`、`src/features/results/*`、`crates/pixel-arena-core/src/report.rs`、测试。

### P5 · #73 原生目标大小（WebP / AVIF）

**要解决的问题**

大小优先模式四个有损格式都沿质量轴搜索；但 cwebp 有 `-size`、avifenc 有 `--target-size`，可以直接按字节收敛。用户反馈希望「支持的原生参数直接用」，不支持的两个（JPEG、JPEG XL）保持质量轴搜索。

**做法（按 #73 的实现决策，适配 0042 的三方式 UI）**

1. **核心库**：
   - `native_target_size_format(format)` 单一能力判定（WebP/AVIF 为真）。
   - `LadderItem` 增 `target_bytes: Option<u64>`；新增 `native_target_size_ladder(target)`；`encode_onestop` / `onestop_product_name` 增 target 实参；目标与质量互斥、0 字节 fail-fast。
   - 原生产物的编码参数文本「WebP 目标 20000 字节」；文件名段 `_size20000`。
   - 仍做内存解码自检（P3 完成后沿用）。
2. **IPC**：
   - `onestop_native_size_ladder(targetBytes)` 或让 `onestop_size_search` 对原生格式返回「原生档位」结果（推荐后者：前端探测循环统一）。
   - 原生格式要显示实际字节，需要一次真实编码探测：新增 `onestop_native_size_probe(targetBytes)`（编码到暂存目录测字节），或让 `onestop_size_search` 对原生格式直接返回 `{ native: true, hitBytes }`；不新增质量点。
   - `onestop_encode` 增 `targetBytes` 可选参数；`FormatEntry` 增 `nativeTargetSize`。
3. **前端（0042 的目标大小方式）**：
   - 探测：原生格式只做一次真实编码探测，拿到实际字节；矩阵一行只有一格「目标 200 KB / 实际 198 KB（命中）」；无 q 值。
   - JPEG/JPEG XL 保持 3 格质量轴搜索。
   - 计数：2 原生 ×1 + 2 搜索 ×3 = 8 项（无损另加）。
   - 结果：结构化 `native_target` + `target_bytes`（P4）显示「目标大小（无质量）」；旧文本兼容。
4. **CLI**：

**验收**

## 5. 风险与约束

- **P2 取消**与 **P4 数据模型**是高风险改动：必须独立提交、带单测、用真实工作区副本验证；取消要保证 `endBusy`、不丢已完成结果。
- **P3 查看器**影响所有图片显示模式；漏一个加载入口就会出现「某模式能看、某模式不能」，要逐模式手工走查。
- **P5 CLI**会改变 `run --target-size` 的输出列值（质量列 `target-size`），属于 CLI 行为变更，需要更新 golden 与 README，并记录决策。
- **P1 去重**的标签匹配在「同参数文本、不同编码器设置」时会误判；「重新生成」复选框是显式逃生口，文档写明。
- 所有涉及界面的任务都要附桌面截图；涉及工作区/导出格式的任务要附旧数据兼容证据。
- 议题「CLOSED 但未落地」是本轮已踩过的坑：所有重落地票必须写明「0.2.1 分支未合入本树」，避免下次再按已关闭处理。
