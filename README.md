# pixel-arena（像素竞技场）

## 这是什么

一个多标签页的编码评测工作台：以「评测」为主、「编码」为辅，用来对比不同图片/视频编码格式的画质和压缩效率。日常在 Windows 上当桌面程序用，开发在 WSL 里进行。

当前进度：

- 标签页（跑分组）与评测轮管理：新建、重命名、关闭标签页，组内新建/改名/删除评测轮、切换轮次。跑分组分「图片跑分组 / 视频跑分组」两种类型，新建时在旁边下拉里选好，之后不可更改；图片组只有图片评测功能（外部导入 + 一站式 + 编码阶梯），视频组只有视频导入与逐帧同步对比，两类标签可同时打开互不干扰。
- 外部导入模式跑分：在评测轮里经系统文件对话框选一张原图与多张跑分图（PNG / JPEG / WebP / AVIF / JPEG XL），点「开始跑分」逐张计算 PSNR / SSIM / MS-SSIM / Butteraugli / SSIMULACRA2 五项指标；结果表给出文件大小、体积比、各指标与排名，任一列可点击排序，跑分失败会在行内给出中文原因。
- 胶囊式文件管理：已选文件以胶囊标签展示——原图/原视频胶囊点击即可重选替换，每张跑分图/每段跑分视频胶囊带 × 可单独移除（其余文件与跑分结果不受影响）；过长的文件名自动中间截断并保留扩展名，悬浮胶囊、结果表或状态栏可见完整路径。
- 一站式跑分（完整编码阶梯）：评测轮里选好原图后，点「一站式跑分」按勾选项自动生成完整编码阶梯并逐张跑分进结果表——有损 JPEG（MozJPEG）/ WebP（libwebp）/ AVIF（libaom）/ JPEG XL（libjxl）× 质量 60 / 75 / 90，外加无损对照组（PNG / 无损 WebP / 无损 JXL，像素与原图逐位一致）。格式、质量档与无损组都能勾选/取消（默认全开），进度逐项显示在状态栏（如「正在生成 AVIF q75（5/12）」），某项失败不影响其余项。各编码器首次使用需联网下载（sha256 校验后存应用数据目录，之后离线可用）。AVIF/JXL 产物在查看器里经自动生成的 PNG 代片显示。
- 视频外部导入跑分：同一轮评测里可再选一段原视频与多段跑分视频（MP4 / MKV / WebM 等），点「开始视频跑分」逐对计算 VMAF / PSNR / SSIM 与耗时；首次使用会自动下载一次 ffmpeg（约 40MB，之后直接复用）。
- 视频逐帧同步对比：视频区块里原视频与跑分视频齐备后出现「逐帧对比」区，两路画面在同一时间点定格并排（分屏 / 滑动 / 2×2 网格），时间轴拖动两路同时定位，±1 帧按帧长精确步进，定位伪影出现的时刻。
- BD-rate 对比汇总：跑分完成后结果表下方按编码格式汇总 BD-rate（Bjøntegaard delta 码率，默认以 JPEG 为参照，负值 = 同画质下更省码率），无损组与点数不足的格式会给出中文说明。
- 导出评测报告：评测轮可一键导出 CSV（指标表 + 视频小节 + BD-rate 汇总，进表格软件用）或自包含 HTML 报告（简体中文、含原图与路径、指标表与 BD-rate 表，可直接分享），导出内容与界面结果同源一致。保存对话框的默认文件名取自原图名（如原图 `xxx.jpg` → 默认导出 `xxx.csv` / `xxx.html`，未选原图时沿用评测轮名）；CSV 带 UTF-8 BOM，Excel 直接打开中文不乱码。
- 对比查看器（第一批）：**左右分屏**（两栏并排、同步缩放平移，可放大到像素级）与**滑动对比**（拖动分割线在同一画面内切换原图与跑分图）。选中原图与跑分图后自动出现，滚轮缩放（光标为锚点）、拖拽平移、双击复位；放大超过 100% 后按原始像素显示（不平滑），便于查看压缩伪影。
- 所有改动（含跑分结果）自动保存，重启应用后完整恢复。

对比查看器另支持多视图（2×2 / 3×3 网格）、叠加对比、差异图与闪烁切换（随 T08/T09 合入）。

## 怎么装成正式应用（安装包）

推送 `v*` 标签后，GitHub Actions 会自动产出三端安装包，到仓库的 Actions 运行页面或 Release 页下载：

- **Windows**：NSIS 安装包（`*-setup.exe`，双击安装）与 MSI 安装包，另有便携版 `pixel-arena.exe`（免安装直接双击运行）。Windows 10/11 自带 WebView2，双击即用。
- **Linux**：`.deb`（Debian/Ubuntu）与 `.AppImage`（免安装，`chmod +x` 后直接运行）。
- **macOS**：`.dmg` 镜像与应用包。

## 已知限制（第一版）

- **不签名**：Windows 安装/首次运行会有 SmartScreen「已保护你的电脑」提示（点「更多信息 → 仍要运行」）；macOS 首次打开需**右键 → 打开**绕过 Gatekeeper（未购买开发者证书公证）。
- **首次使用要联网**：一站式跑分的各编码器与视频跑分的 ffmpeg 不随安装包内置（安装包保持小体积），首次触发时自动下载、经 sha256 校验后存到应用数据目录 `tools/`，之后离线可用。Windows 侧 ffmpeg 约 150MB，下载进度在状态栏显示。
- **AVIF / JPEG XL 的显示是代片**：WebView 原生解不了这两种格式，查看器里显示的是工具自动生成的 PNG 代片（跑分与结果表始终用产物本身，见决策 0012）。
- **修复前跑分的旧评测轮只有 PSNR / SSIM 两列有值**：结果表的五列由每张跑分图的存档数据驱动——早期版本跑分只存了两项指标，旧评测轮不会凭空补齐，在该轮里重新点「开始跑分」即可算全五列（不是软件故障）。
- **Windows 一站式的 AVIF 暂不可用**：AVIF 的 Windows 编码器工件需在 CI 自建（libavif 无官方预编译），其余格式（JPEG/WebP/JPEG XL + 全部无损组）开箱可用；补齐前 AVIF 档位会给出中文说明。
- **macOS 端一站式与视频暂不可用**：macOS 的编码器与 ffmpeg 分发随后续票落实，当前 macOS 产物可用外部导入模式的图片跑分与全部对比查看功能；触发一站式会得到中文说明。
- **Linux 看部分视频需要系统解码器**：逐帧对比的画面解码走系统 GStreamer，H.264 等格式需要 `gst-libav`（画面区会给中文提示），VP8/VP9 的 WebM 可直接看；视频**跑分**不受影响（走内置 ffmpeg）。

## 环境搭建（一次性）

需要 Rust、Node.js 和几个系统库。系统依赖（webkit2gtk-4.1、gtk3 等）在当前开发环境已预装，下面的 apt 命令经 `apt-get install --dry-run` 验证过包名：

```bash
# 1. Rust（官方安装器，装到用户目录）
curl --proto '=https' --tlsv1.2 -sSf https://sh.rustup.rs | sh

# 2. Node.js 22（用 nvm 或系统包管理器均可，本机为 Node 22）

# 3. Tauri 在 Linux 上的系统依赖（Debian/Ubuntu 包名）
sudo apt-get install -y libwebkit2gtk-4.1-dev build-essential curl wget file \
  libxdo-dev libssl-dev libayatana-appindicator3-dev librsvg2-dev

# 4. 前端依赖（在仓库根目录执行）
npm install
```

## 怎么启动（看到桌面窗口）

在仓库根目录执行：

```bash
npm run tauri dev
```

## 日常怎么用

- 桌面应用：开发期 `npm run tauri dev` 启动；正式安装包由 CI 出三端产物（见「怎么装成正式应用」）。
- 跑分组（标签页）：先在「＋ 新建跑分组」左侧下拉选好类型（图片跑分组 / 视频跑分组），再点按钮建一个标签页（类型创建后不可更改，评测轮栏会显示当前组类型）；**单击**标签切换，**双击**标签名重命名，点标签上的 **×** 关闭。打开旧版本留下的工作区会自动归类：组内任一轮含视频归为视频跑分组，其余（含空组）归为图片跑分组，原有数据不丢。
- 评测轮：标签页下方一行是组内评测轮，点「＋ 新建评测轮」添加；**单击**切换轮次，**双击**改名，点 **×** 删除。
- 自动保存：所有改动立即保存，退出应用再打开，跑分组与评测轮原样恢复（保存位置见下方「工作区文件在哪」；不想要这个行为可用「设置」里的记录状态开关关闭，见下）。
- 设置：点窗口右上角的「设置」按钮打开设置面板，改完立即生效、重启后仍有效——
  - **记住上次状态**（默认开）：关闭后每次启动都是干净状态（不恢复标签页、窗口大小与最近选文件目录）；重新打开后恢复行为照旧。
  - **界面主题**：浅色 / 深色 / 跟随系统，切换立即生效（含对比查看器画面区域）。
  - **默认导出目录**：设置后「导出 CSV / HTML」的保存对话框直接定位到该目录。
  - **编码器（高级）**：可为一站式编码的各工具（cjpeg / cwebp / avifenc / cjxl，及 AVIF 代片解码 avifdec）指定自定义可执行文件路径，用于排障或用自己的构建；路径填错保存时就会被拦下提示，清空即恢复内置自动下载的编码器。
- 对比查看器：评测轮里选好原图与跑分图后，结果表上方出现「对比查看器」。用「左右分屏 / 滑动对比」按钮切换模式，下拉框选择要对比的跑分图；**滚轮**以光标为中心缩放，**按住拖动**平移画面，**双击**复位到整图，滑动模式下**拖动白色分割线**（带 ⟷ 把手）可左右扫动对比。
- 一站式跑分（完整编码阶梯）：评测轮里只选一张原图，点绿色描边的「一站式跑分」按钮，工具按按钮下方的勾选自动生成跑分图并自动跑分——格式（JPEG / WebP / AVIF / JPEG XL）、质量档（60 / 75 / 90）与无损组（PNG / 无损 WebP / 无损 JXL）都可自由勾选，默认全开共 15 份。进度逐项亮在窗口右上角状态栏；生成失败会有中文提示，已成功的项照常进入结果表。编码器首次使用会自动下载（下载进度即状态栏提示，之后离线可用）。AVIF / JPEG XL 产物在对比查看器里显示的是工具自动生成的 PNG 代片（画面与产物解码一致）。
- 视频跑分：视频跑分组评测轮里的「视频跑分」区块——「选择原视频」定基准，「添加跑分视频」多选已压缩产物，「开始视频跑分」逐对出结果（VMAF / PSNR / SSIM / 耗时）。首次点跑分会先自动下载 ffmpeg（约 40MB，下载进度显示在顶部状态栏，之后直接复用）；VMAF 越接近 100 越好，视频 SSIM 是 ffmpeg 口径，与图片 SSIM 数值不可直接比较。视频跑分依赖的 ffmpeg 存放在应用数据目录的 `tools/` 文件夹（Linux 示例：`~/.local/share/io.github.boxmiao007.pixelarena/tools/`），一站式下载的各编码器也在同一位置。
- 视频逐帧对比：视频区块里已有原视频和跑分视频时，下方出现「逐帧对比」区（左右下拉可换两路视频）。**时间轴**拖动即两路同时 seek，**−1 帧 / +1 帧**按 30fps 之类真实帧长精确走帧，右侧显示当前时间 / 总时长（以最短一段为准）；画面缩放平移与图片查看器同款（滚轮缩放、拖拽平移、双击复位），滑动模式下拖动分割线扫动对比。帧率由 ffprobe 读取（与 ffmpeg 同目录），读不到时步进按钮置灰、时间轴仍可用。Linux 端 H.264 等 WebKitGTK 缺解码器的格式会在画面区给出中文提示（不影响跑分），VP8 / VP9 的 WebM 可直接解码。
- BD-rate 汇总：跑分完成后，结果表下方出现「BD-rate 汇总」表（参照格式默认 JPEG，会在表头标注）。BD-rate 为负表示同画质下比参照更省码率（更优）；「样本不足」表示该格式有效的有损质量点少于 3 个，无损组（像素与原图一致）不参与 BD-rate 拟合、单独注明。
- 导出报告：结果表上方有「导出 CSV」「导出 HTML」按钮，选好保存位置即写出当前评测轮的完整结果——CSV 含图片指标表、视频小节与 BD-rate 汇总（英文列名、inf 表示两图逐像素一致），HTML 是可直接打开分享的中文报告（含原图路径、指标表与 BD-rate 表）。两者与界面显示同一份数据，某格式点数不足时报告里同样注明。保存对话框默认名取自原图名（`xxx.jpg` → `xxx.csv`/`xxx.html`，未选原图时沿用评测轮名）；CSV 带 UTF-8 BOM，Excel 直接打开中文不乱码。
- 命令行批量跑分（外部导入模式）：选好一张原图和几张已压缩的跑分图后，执行
  `cargo run -p pixel-arena-cli -- score --reference 原图.png --candidates 跑分图1.jpg 跑分图2.webp`，
  就得到一张 CSV 指标表（PSNR、SSIM、MS-SSIM、Butteraugli、SSIMULACRA2、文件大小、体积比），
  重定向存成文件后 Excel 可直接打开（输出带 UTF-8 BOM，中文路径不乱码）；加 `--format json` 则输出 JSON；加 `--format html` 则输出自包含的
  简体中文 HTML 报告（内联样式、含生成时间，浏览器直接打开即可分享）。指标口径：MS-SSIM 越接近 1 越好；
  Butteraugli 是距离分，0 表示完全一致、约 1.0 是刚好可察觉；SSIMULACRA2 是质量分，
  100 表示完全一致。进度与错误提示是简体中文，出错时按提示处理即可
  （支持的图片格式：PNG/JPEG/WebP/AVIF/JPEG XL；AVIF 跑分需先有一站式生成过 AVIF 产物
  以便自动安装解码工具）。
- 命令行一站式批量跑分（run 子命令）：只有一张原图时，执行
  `cargo run -p pixel-arena-cli -- run --reference 原图.png`，
  工具按完整默认编码阶梯（有损 JPEG / WebP / AVIF / JPEG XL × 质量 60 / 75 / 90，
  外加无损对照组 PNG / 无损 WebP / 无损 JXL，共 15 份）自动生成跑分图并逐张跑分，
  输出与 score 同栏位的 CSV 指标表（另加 format、quality 两列；`--format json` 输出 JSON，
  `--format html` 输出自包含中文报告，质量列在报告里对无损组显示「无损」）。
  可用 `--formats jpeg webp`、`--qualities 60 75`、`--lossless png` 收窄范围
  （这三个参数不带值表示该组不跑）；`--out 目录` 保留产物（默认在系统临时目录新建一个文件夹，
  结束时 stderr 会提示路径）；`--tools-dir 目录` 指定编码器安装目录（默认与桌面应用共用）。
  编码器首次使用自动下载（stderr 显示「正在下载编码器 …」），装过一次后离线可用；
  某一档生成失败不影响其余档位，失败原因逐项中文提示，有失败时退出码为 1。
- 按基准质量自动取点（质量优先模式）：`run --reference 原图.png --baseline-quality 75`
  用统一基准值（0–100）在每个有损格式自身参数范围内自动取点——基准 ±15（贴边时向内补足），
  每格式至少 3 个质量点 + 无损对照组，保证 BD-rate 曲线有效；不传该参数时基准取 75，
  输出与默认阶梯完全一致。
- 按期望大小压缩（大小优先模式）：`run --reference 原图.png --target-size 200`
  （单位 KB）让每个有损格式自动搜索逼近目标大小的质量点，并自动补邻近点保住 BD-rate；
  目标不可达（过小压不到 / 过大放松到顶）时取最接近点，CSV/JSON 追加 note 列、
  HTML 追加「备注」列标注原因与实际大小（不传 `--target-size` 时输出与原来完全一致，
  没有该列）。`--baseline-quality`、`--qualities`、`--target-size` 三者互斥。

## 工作区文件在哪

跑分组与评测轮保存在应用数据目录下的 `workspace.json`，设置面板的各选项保存在同目录的 `settings.json`（两者独立，删掉 settings.json 只会恢复默认设置，不影响评测数据）：

- Linux：`~/.local/share/io.github.boxmiao007.pixelarena/workspace.json`（设置：同目录 `settings.json`）
- Windows：`%APPDATA%\io.github.boxmiao007.pixelarena\workspace.json`（设置：同目录 `settings.json`）
- macOS：`~/Library/Application Support/io.github.boxmiao007.pixelarena/workspace.json`（设置：同目录 `settings.json`）

首次启动还没有这个文件，属正常现象，新建跑分组后即生成。
