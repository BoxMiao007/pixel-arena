# pixel-arena（像素竞技场）

## 这是什么

一个多标签页的编码评测工作台：以「评测」为主、「编码」为辅，用来对比不同图片/视频编码格式的画质和压缩效率。日常在 Windows 上当桌面程序用，开发也在 Windows 上进行（Linux/macOS 产物由 CI 构建）。

当前进度：

- 桌面工作台四区：左栏跑分组、中间舞台（图片对比 / 视频对比）+ 可折叠结果坞、右栏检视器。跑分组分「图片跑分组 / 视频跑分组」两种类型，新建时选好之后不可更改；图片组只有图片评测功能（外部导入 + 一站式 + 编码阶梯），视频组只有视频导入与逐帧同步对比，两类分组可同时打开互不干扰。常用动作都有快捷键，文件可从资源管理器直接拖进窗口。
- 外部导入模式跑分：在评测轮里经系统文件对话框选一张原图与多张跑分图（PNG / JPEG / WebP / AVIF / JPEG XL），点「开始跑分」逐张计算 PSNR / SSIM / MS-SSIM / Butteraugli / SSIMULACRA2 五项指标；结果表给出文件大小、体积比、各指标与排名，任一列可点击排序，跑分失败会在行内给出中文原因。
- 来源管理：检视器里原图与跑分图分别是两行式清单（文件名 + 大小 / 体积比 / 编码参数），原图点「更换原图」即可替换，每张跑分图行尾的 × 可单独移除（其余文件与跑分结果不受影响）；过长的文件名单行省略，悬浮可见完整路径。
- 一站式跑分（编码阶梯，三种方式）：评测轮里选好原图后，在检视器「编码阶梯」分区展开，在「单点 / 阶梯 / 目标大小」里选一种——**单点**（默认）：每个有损格式只压「基准质量」这一档，打开就能快速跑一轮；**阶梯**：同一根基准质量拉杆，每个格式在基准上下各取一档（共 3 档），便于横向比较档位；**目标大小**：用对数滑杆粗调 + 精确输入框定目标大小，点「探测目标大小」后每个格式自动逼近并显示实测字节与命中点，确认清单后再「生成并跑分」。有损格式 JPEG（MozJPEG）/ WebP（libwebp）/ AVIF（libaom）/ JPEG XL（libjxl）与无损对照组（PNG / 无损 WebP / 无损 JXL）在同一张矩阵里勾选，无损对照默认不选；矩阵项数就是实际生成项数，生成后只跑本次新产物，整轮重算仍在「原图」分区的跑分入口。进度逐项显示（「正在生成 AVIF q75（5/12）」），某项失败不影响其余项。编码器已随安装包内置（设置页可看到「内置 + 版本号」，也可改用外部路径）。AVIF/JXL 产物在查看器里经自动生成的 PNG 代片显示。
- 视频高级创建（配置与命令行预览）：视频跑分组 → 检视器「高级」→「高级创建…」，选原视频、按格式挑编码器（ffmpeg 实际枚举 + 固定映射）、逐项配参数并实时预览命令行（可复制）；确认后新建评测轮并把配置摘要与命令行写进「本轮备注」。本版本不做视频自动编码：复制命令行自行编码后，用「添加跑分视频」把产物导进来即可。
- 视频外部导入跑分：视频跑分组里选一段原视频与多段跑分视频（MP4 / MKV / WebM 等），点「开始视频跑分」逐对计算 VMAF / PSNR / SSIM 与耗时；首次使用前需在设置页「应用内下载」一次 ffmpeg（约 40MB，之后直接复用；未就绪时标题栏有提醒、跑分分区里有说明与设置入口）。
- 视频逐帧同步对比：视频组的舞台就是逐帧对比，两路画面在同一时间点定格并排（分屏 / 滑动 / 网格），时间轴拖动两路同时定位，±1 帧按帧长精确步进，也可用方向键逐帧、Shift 十帧，定位伪影出现的时刻。
- 效率对比：结果坞第二个页签按体积排序列出每张跑分图，标出「没有更小又更高画质」的划算项，并写明不划算的图不如哪一张（体积多多少、画质低多少）。1 张图就有数据，2 张起判划算，不用先凑一条质量曲线。
- 导出评测报告：评测轮可一键导出 CSV（指标表 + 视频小节，进表格软件用）或自包含 HTML 报告（简体中文、含原图与路径、指标表，可直接分享），导出内容与界面结果同源一致。保存对话框的默认文件名取自原图名（如原图 `xxx.jpg` → 默认导出 `xxx.csv` / `xxx.html`，未选原图时沿用评测轮名）；CSV 带 UTF-8 BOM，Excel 直接打开中文不乱码。
- 对比查看器（第一批）：**左右分屏**（两栏并排、同步缩放平移，可放大到像素级）与**滑动对比**（拖动分割线在同一画面内切换原图与跑分图）。选中原图与跑分图后自动出现，滚轮缩放（光标为锚点）、拖拽平移、双击复位；放大超过 100% 后按原始像素显示（不平滑），便于查看压缩伪影。
- 所有改动（含跑分结果）自动保存，重启应用后完整恢复。

对比查看器另支持多视图（2×2 / 3×3 网格）、叠加对比、差异图与闪烁切换（随 T08/T09 合入）。

## 怎么装成正式应用（安装包）

推送 `v*` 标签后，GitHub Actions 会自动产出三端安装包，到仓库的 Actions 运行页面或 Release 页下载：

三端安装包均已**内置四个跑分编码器**（JPEG / WebP / AVIF / JPEG XL，含 AVIF 代片解码），装完即可一站式跑分，无需联网下载编码器。

- **Windows**：NSIS 安装包（`*-setup.exe`，双击安装）与 MSI 安装包，另有便携包 `Pixel-Arena_<版本>_x64-portable.zip`（如 0.1.5 即 `Pixel-Arena_0.1.5_x64-portable.zip`，解压出 `PixelArena/` 文件夹后双击 `pixel-arena.exe` 直接运行，免安装）。Windows 10/11 自带 WebView2，双击即用。
- **Linux**：`.deb`（Debian/Ubuntu）与 `.AppImage`（免安装，`chmod +x` 后直接运行）。
- **macOS**：`.dmg` 镜像与应用包。

## 已知限制（第一版）

- **不签名**：Windows 安装/首次运行会有 SmartScreen「已保护你的电脑」提示（点「更多信息 → 仍要运行」）；macOS 首次打开需**右键 → 打开**绕过 Gatekeeper（未购买开发者证书公证）。
- **视频跑分前需先下载 ffmpeg（约 40MB，一次性）**：ffmpeg 不随安装包内置（含 libvmaf 的静态构建体积大），且应用**不会自动下载**——首次视频跑分前，请到「设置 → FFmpeg（视频跑分）」点「应用内下载」（进度显示在设置窗口里，关掉设置窗口也不中断，经 sha256 校验后存应用数据目录 `tools/`，之后离线可用），或指定本机已有的 ffmpeg。FFmpeg 未就绪时标题栏显示提醒徽标、点开即进设置；图片评测（一站式/外部导入）不受影响。
- **AVIF / JPEG XL 的显示是代片**：WebView 原生解不了这两种格式，查看器里显示的是工具自动生成的 PNG 代片（跑分与结果表始终用产物本身，见决策 0012）。
- **修复前跑分的旧评测轮只有 PSNR / SSIM 两列有值**：结果表的五列由每张跑分图的存档数据驱动——早期版本跑分只存了两项指标，旧评测轮不会凭空补齐，在该轮里重新点「开始跑分」即可算全五列（不是软件故障）。
- **Windows 一站式 AVIF 用官方编码器工件**：libavif v1.4.2 起官方 Release 附带预编译工件（avifenc/avifdec 全静态），已随安装包捆绑；捆绑缺失时不再联网下载，报错指引官方发布页（可在设置页指定外部路径接入）。
- **macOS 端一站式与视频跑分可用（Apple Silicon）**：编码器（MozJPEG/WebP/AVIF/JPEG XL）已随安装包捆绑，ffmpeg 经设置页「应用内下载」获取（与其他平台同一锁定来源）；Intel Mac 无官方工件，触发会得到中文说明。macOS 产物可用全部对比查看功能。
- **Linux 看部分视频需要系统解码器**：逐帧对比的画面解码走系统 GStreamer，H.264 等格式需要 `gst-libav`（画面区会给中文提示），VP8/VP9 的 WebM 可直接看；视频**跑分**不受影响（走内置 ffmpeg）。

## 环境搭建（一次性）

需要 Rust（MSVC 工具链）、Node.js 和 C++ 构建工具。当前开发机是 Windows，已按下面口径装齐（`cargo test --workspace` 与 `npm install` 实测通过）：

- **Rust**：rustup + MSVC 工具链，默认 host `x86_64-pc-windows-msvc`（本机 cargo/rustc 1.99.1，装在 `D:\dev\env\rust`）。
- **Node.js**：22 或更高（本机 v26.12.1、npm 11.20.0）。
- **C++ 构建工具**：Visual Studio Build Tools，勾选「使用 C++ 的桌面开发」——Tauri 的 Rust 依赖靠它提供链接器。
- **WebView2 运行时**：Windows 10/11 一般随系统预装（本机 155.0.4283.62）；缺失时装微软的 Evergreen 运行时。
- **前端依赖**：在仓库根目录执行 `npm install`。

Linux/macOS 的系统依赖（webkit2gtk 等）只在 CI 构建三端产物时需要，本机开发不用装。

## 日常怎么用

- 桌面应用：开发期 `npm run tauri dev` 启动；正式安装包由 CI 出三端产物（见「怎么装成正式应用」）。
- 界面分四块：左边是**跑分组栏**，中间上方是**舞台**（对比查看器 / 视频对比）、下方是可折叠的**结果坞**（评分表、效率对比、视频指标；折叠后只收成一条页签栏，点它或页签即可再展开），右边是**检视器**（原图与跑分、跑分图、编码阶梯）。左栏与检视器的边界都能用鼠标拖拽调宽（双击分隔条恢复默认，聚焦后方向键微调），宽度会记住；结果坞的上边界可以上下拖高。应用顶栏左侧显示当前分组与评测轮，右侧是状态、快捷键帮助与设置；应用名在系统窗口标题栏。舞台可以按 `F` 进入**沉浸模式**（隐藏两侧与结果坞，只看画面），再按 `F` 或 `Esc` 退出。
- 跑分组：左栏底部「＋ 新建跑分组」先选类型（图片 / 视频），再在弹窗里填名字（预填「图片跑分组 N」，回车即建）。**单击**切换，**双击**改名，行右侧的 **⋯** 或右键出菜单（重命名 / 关闭）。关闭有内容的跑分组会先弹确认，说明会丢弃几个评测轮；空组直接关闭。类型创建后不可更改。
- 评测轮：窗口工作栏一行是组内评测轮，点「＋」新建（可改名）。**单击**切换，**双击**改名，右键或 `F2`——右键菜单里可删除（有内容时先确认）。`Ctrl+1…9` 直接切到第 N 个跑分组。
- 拖文件进来：把图片从资源管理器拖进窗口即可——拖到「原图」区设为原图，拖到「跑分图」区或舞台追加跑分图；视频组同理。首次还没有原图时，拖一张图片到舞台会直接设为原图，其余图片自动进入跑分图列表。
- 自动保存：所有改动立即保存，退出应用再打开，跑分组与评测轮原样恢复（保存位置见下方「工作区文件在哪」；不想要这个行为可用「设置」里的记录状态开关关闭，见下）。
- 快捷键：`Ctrl+N` 新建轮、`Ctrl+Shift+N` 新建分组、`Ctrl+O` 选原图、`Ctrl+Shift+O` 加跑分图、`Ctrl+Enter` 开始跑分、`Ctrl+E` 导出、`Ctrl+,` 设置、`Ctrl+B / I / J` 折叠左栏 / 检视器 / 结果坞、`F` 沉浸、`?` 打开快捷键表。查看器里 `1–6` 切模式、`空格` 闪烁、`+`/`-` 缩放、`0` 适应、`Shift+0` 原始像素；视频里 `←/→` 逐帧（`Shift` 十帧）、`Home/End` 首末帧、`空格` 播放暂停。
- 设置：点窗口右上角的齿轮（或 `Ctrl+,`）弹出居中的设置窗口，左侧分区（外观 / 记录 / 跑分与导出 / FFmpeg / 编码器 / 关于），改动**逐项即时保存**，失败就地红字并保留你的输入；底部「全部恢复默认」会先确认并按实际填过的路径条数说明影响——
  - **记住上次状态**（默认开）：关闭后每次启动都是干净状态（不恢复跑分组、窗口大小与最近选文件目录）；重新打开后恢复行为照旧。
  - **界面主题**：浅色 / 深色 / 跟随系统，切换立即生效（含图像判定区底色）。
  - **跑分并发度**（默认 1/2 核心）：多张跑分图/跑分视频并行计算时最多同时占用的逻辑核比例，四档 1/4、1/2、3/4、全部可选；默认只用一半核心，跑分再快电脑也不卡。
  - **文件名冲突**（默认「自动追加序号」）：跑分产物与已有文件同名时默认追加 `_1`/`_2`（永不覆盖）；改成「询问」后写入前弹窗让你拍板覆盖 / 跳过，可一次管住本次剩余冲突。
  - **默认导出目录**：设置后导出保存对话框直接定位到该目录。
  - **FFmpeg（视频跑分）**：可「应用内下载」（一次约 40MB，界面显示进度，关掉设置窗口也不中断），或指定本机已有的 ffmpeg；每行显示来源状态（内置 / 外部 / 未配置 / 不可用）、版本与实际生效路径，「复制诊断信息」可一键复制环境摘要。
  - **编码器**：可为一站式编码的各工具（cjpeg / cwebp / avifenc / cjxl，及 AVIF 代片解码 avifdec）指定自定义可执行文件路径，用于排障或用自己的构建；路径填错保存时就会被拦下提示，清空即恢复内置编码器（安装包已捆绑）。
- 对比查看器：工具条上六个模式随点随切——**分屏**（原图 + 每张跑分图各一栏，栏宽不足时横向滚动，每栏左上角下拉可单独换图）、**多视图**（2×2 / 3×3 网格，格子多了双向滚动，每格下拉可换图；每格按自己的图片尺寸贴满格子，所以同一屏里各格看起来一样大，滚轮放大仍然同步）、**滑动**（拖动分割线在同一画面内扫动对比）、**叠加**（拖动不透明度滑杆把跑分图半透明叠在原图上）、**差异**（亮度差超阈值的像素标黄红热区，滑杆调灵敏度）、**闪烁**（自动交替原图与跑分图；长按画面看对比图、松手回原图）。滑动 / 叠加 / 差异 / 闪烁这四种单画面对比模式，点工具条上的「滑动：某张图」即可打开下拉换对比图（列出全部跑分图并高亮当前那张）；分屏与多视图则在每栏 / 每格左上角的下拉里换。缩放平移所有模式通用：**滚轮**以光标为中心缩放，**按住拖动**平移，**双击**复位到适应窗口；放大超过 100% 后按原始像素显示，便于看压缩伪影。分辨率不同的跑分图（比如缩小过的产物）不会一小一大：分屏每栏、多视图每格，以及滑动 / 叠加 / 闪烁画面里的跑分图层，都会先按自己的尺寸贴满窗格，滚轮放大时再一起同比例放大；缩放读数与比例尺跟随指针所在的那一栏/格（单画布模式以原图为准）。差异图要求两张图尺寸相同，不一致时会提示改用叠加。加载失败会给出原因与「重试 / 复制路径」；AVIF / JPEG XL 显示的是工具生成的 PNG 代片。在本轮跑分的图里，多视图每格右上角会挂**判断徽标**——画质最好 / 体积最小 / 综合最优（同一份判定也出现在结果表与「跑分图」列表，鼠标悬停能看到具体指标数值）；在画面、每栏/每格或结果表的图片行上**右键**可以「打开图片 / 打开文件位置 / 另存为… / 复制路径」（打开与定位交给系统程序，另存只是原样拷贝，不做格式转换）。
- 一站式跑分（单点 / 阶梯 / 目标大小）：评测轮里只选一张原图，在检视器「编码阶梯」分区展开——三种方式互斥，默认**单点**：拖「基准质量」拉杆（0–100，默认 75），每个有损格式只压这一档（JXL 上限 95），默认 4 项；**阶梯**沿用同一根拉杆，每个格式在基准上下各取一档（基准 75 即 60/75/90，共 12 项）；**目标大小**把主参数换成目标大小（对数滑杆粗调 + 精确输入 + KB/MB），先点「探测目标大小」让每个格式真实编码逼近，矩阵里显示每档实测字节与命中点，不可达会在行尾标注，确认后「生成并跑分」。格式与无损组在同一张矩阵里勾选，无损对照默认不选；矩阵项数就是实际生成项数，生成后只跑本次新产物。产物存在**原图所在目录的「Pixel Arena」文件夹**，文件名格式为 `原图名_编码器_质量（或 lossless）.扩展名`，重跑同一档不覆盖、自动追加 `_1`/`_2`。
- 参数变体（图片跑分组，给同一条原图试一套自己的编码参数）：入口唯一——「跑分图」分区顶部的**「＋ 从原图新建编码」**（已跑分 / 未跑分的图都不再从某张图复制参数，因为那份参数并不出自这张图）。在弹窗里配好编码器与参数、点「完成」即可；也可以点「＋ 添加编码器」一次配多条，一条配置一张可折叠的卡；同一张卡里换编码器会清空上一个编码器的高级参数行（各家的标志互不通用），质量数值与目标大小保留，方便等质量横比。没生成的变体就排在跑分图列表末尾（虚线边、未跑分），点一下就地调参、× 删除；点「开始跑分」会先把它生成出来再整轮跑分，产物直接进**当前**评测轮，与普通跑分图同表对比（带「高级」角标），不新建轮。只补跑改过的用「重跑改过的（N 张）」：参数改过、原图换过、从没跑过、上次失败的才跑，其余跳过。跑分中途有失败时状态栏说「跑分结束」而不是「跑分完成」，并给出失败条数；「跑分汇总」弹窗会逐条列出失败原因，列表行上的「上次失败」徽标、编辑卡顶部那枚也能点开看同一份「失败说明」。变体与参数只活在这次运行里，重启应用后归零（磁盘产物保留）。
- 视频跑分：视频跑分组评测轮里，检视器「原视频 / 跑分视频」定好来源后，点「开始视频跑分」整轮并行出结果（VMAF / PSNR / SSIM / 耗时；同时打开的 ffmpeg 进程数受设置里的跑分并发度约束，进度 N/M 显示在标题栏与分区里）。ffmpeg 未就绪时入口会给出说明与「前往设置」；VMAF 越接近 100 越好，视频 SSIM 是 ffmpeg 口径，与图片 SSIM 数值不可直接比较。跑分结果在结果坞的「视频指标」页签。
- 视频高级创建：视频组里想用 ffmpeg 自己压一段时，点检视器「高级」里的「高级创建…」——选原视频、挑编码器（如 libx264 / libx265 / libvpx-vp9）、配质量与参数，面板里能实时看到完整命令行并可复制；确认后新建一轮，配置与命令行会写进「本轮备注」长期可见。压完的同名产物用「添加跑分视频」导入即可开始跑分。
- 视频逐帧对比：视频组的舞台就是逐帧对比——**分屏 / 滑动 / 网格**三种模式，画面下方是**时间轴**：拖动两路同时定位，`−1 帧 / +1 帧` 按真实帧长精确走帧，`←/→` 逐帧、`Shift+←/→` 十帧、`Home/End` 首末帧、`空格` 播放暂停；右侧显示当前帧号 / 总帧数、时间与 fps。画面缩放平移与图片查看器同款。Linux 端 H.264 等 WebKitGTK 缺解码器的格式会在画面区给出中文提示（不影响跑分），VP8 / VP9 的 WebM 可直接解码。
- 结果坞：默认展示「评分表」——原图基准行固定在顶部，每张跑分图一行（大小、体积比、编码参数、五项指标、状态与备注）。点表头三次循环切换排序（无 → 首选方向 → 反向），指标列固定顺序、每列最优值高亮；失败行的状态可点开看完整原因并复制；列可以在「列」菜单里显隐；点某一行会让舞台切到那张跑分图。折叠结果坞时它不会整块消失，只收成一条 36px 的页签栏：点页签、条本身或右侧箭头都能再展开，`Ctrl+J` 也能来回切。跑分完成后「效率对比」页签按体积排序列出每张图，标出更划算的（同体积画质更高、同画质体积更小），并写明不划算的图不如哪一张。
- 导出报告：工作栏右侧「导出」菜单（或 `Ctrl+E`）——导出 CSV / 导出 HTML 会写出当前评测轮的完整结果（CSV 含图片指标表与视频小节；HTML 是可直接分享的中文报告），另有「复制为 CSV / 复制为 Markdown」直接进剪贴板。保存对话框默认名取自原图名（`xxx.jpg` → `xxx.csv`/`xxx.html`，未选原图时沿用评测轮名）；CSV 带 UTF-8 BOM，Excel 直接打开中文不乱码。

- 命令行批量跑分（外部导入模式）：选好一张原图和几张已压缩的跑分图后，执行
  `cargo run -p pixel-arena-cli -- score --reference 原图.png --candidates 跑分图1.jpg 跑分图2.webp`，
  就得到一张 CSV 指标表（PSNR、SSIM、MS-SSIM、Butteraugli、SSIMULACRA2、文件大小、体积比），
  重定向存成文件后 Excel 可直接打开（输出带 UTF-8 BOM，中文路径不乱码）；加 `--format json` 则输出 JSON；加 `--format html` 则输出自包含的
  简体中文 HTML 报告（内联样式、含生成时间，浏览器直接打开即可分享）。指标口径：MS-SSIM 越接近 1 越好；
  Butteraugli 是距离分，0 表示完全一致、约 1.0 是刚好可察觉；SSIMULACRA2 是质量分，
  100 表示完全一致。进度与错误提示是简体中文，出错时按提示处理即可
  （支持的图片格式：PNG/JPEG/WebP/AVIF/JPEG XL；AVIF 跑分需先有一站式生成过 AVIF 产物
  以便自动安装解码工具）。
- 命令行一站式批量跑分（run 子命令）：只有一张原图时，执行
  `cargo run -p pixel-arena-cli -- run --reference 原图.png`，
  工具按完整默认编码阶梯（有损 JPEG / WebP / AVIF / JPEG XL × 质量 60 / 75 / 90，
  外加无损对照组 PNG / 无损 WebP / 无损 JXL，共 15 份）自动生成跑分图并逐张跑分，
  输出与 score 同栏位的 CSV 指标表（另加 format、quality 两列；`--format json` 输出 JSON，
  `--format html` 输出自包含中文报告，质量列在报告里对无损组显示「无损」）。
  可用 `--formats jpeg webp`、`--qualities 60 75`、`--lossless png` 收窄范围
  （这三个参数不带值表示该组不跑）；`--out 目录` 保留产物（默认在系统临时目录新建一个文件夹，
  结束时 stderr 会提示路径）；`--tools-dir 目录` 指定编码器内置落位目录（默认与桌面应用共用）。
  编码器不联网下载：目录里没有（如老版本未捆绑、文件被安全软件移除）时该档报中文错误，
  附官方发布页 URL 与外部路径指引；某一档生成失败不影响其余档位，失败原因逐项中文提示，
  有失败时退出码为 1。
- 按基准质量自动取点（质量阶梯方式）：`run --reference 原图.png --baseline-quality 75`
  用统一基准值（0–100）在每个有损格式自身参数范围内自动取点——基准 ±15（贴边时向内补足），
  每格式至少 3 个质量点 + 无损对照组，便于比较档位；不传该参数时基准取 75，
  输出与默认阶梯完全一致。桌面应用的「单点」方式等价于 `--qualities <基准>`；
  CLI 不传参数时仍按 3 点阶梯跑，批量脚本行为不变。
- 按期望大小压缩（目标大小方式）：`run --reference 原图.png --target-size 200`
  （单位 KB）让每个有损格式自动搜索逼近目标大小的质量点，并自动补邻近点；
  目标不可达（过小压不到 / 过大放松到顶）时取最接近点，CSV/JSON 追加 note 列、
  HTML 追加「备注」列标注原因与实际大小（不传 `--target-size` 时输出与原来完全一致，
  没有该列）。`--baseline-quality`、`--qualities`、`--target-size` 三者互斥。
- 并行跑分：score 与 run 的跑分阶段并行执行，默认同时跑一半逻辑核心（与桌面应用默认一致）；
  `--concurrency N` 可显式指定线程数，传入值自动夹在 [1, 逻辑核数]（如 0 按 1 跑、超界按核数跑）。
  结果顺序与传入顺序一致，并发度不影响任何指标数值；某张跑分图失败时 score 整体报错退出 1，
  run 则继续其余档位、结束统一结算（与原行为一致）。

## 工作区文件在哪

跑分组与评测轮保存在应用数据目录下的 `workspace.json`，设置面板的各选项保存在同目录的 `settings.json`（两者独立，删掉 settings.json 只会恢复默认设置，不影响评测数据）：

- Linux：`~/.local/share/io.github.boxmiao007.pixelarena/workspace.json`（设置：同目录 `settings.json`）
- Windows：`%APPDATA%\io.github.boxmiao007.pixelarena\workspace.json`（设置：同目录 `settings.json`）
- macOS：`~/Library/Application Support/io.github.boxmiao007.pixelarena/workspace.json`（设置：同目录 `settings.json`）

首次启动还没有这个文件，属正常现象，新建跑分组后即生成。
